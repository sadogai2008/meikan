# Meishi — 名刺管理システム

名刺をまとめて管理する軽量Webアプリ。Cloudflare Pages + Hono + D1 で動作します。

## 概要

- **目的**: 紙の名刺をデジタル化し、人脈を「引ける」状態で保持する
- **特徴**: 検索・タグ/部署/会社での絞り込み・お気に入り・詳細ドロワー・CSV入出力・**AIアシスタント**
- **デザイン**: 紙とインクを基調にした落ち着いたUI。カードグリッド＋サイドバー絞り込み

## 主な機能

| 機能 | 説明 |
| --- | --- |
| 名刺一覧 | カードグリッド表示。氏名・ふりがな・会社・部署/役職・タグ・連絡先を一覧化 |
| 全文検索 | 氏名/ふりがな/会社/部署/役職/メール/電話/携帯/住所/メモ/タグを横断検索（スペース区切りでAND） |
| 絞り込み | すべて / お気に入り / タグ / 部署 / 会社（排他切り替え） |
| **AIアシスタント** | 自然言語で絞り込み（例:「広報部署だけまとめて」）。件数集計・CSV出力も指示できる |
| **AIによる内容編集** | 「鈴木さんの部署を営業部に変えて」で編集案を提示。**差分を確認して「適用する」を押すまで保存されません** |
| **AI一括タグ操作** | 「広報の人に『展示会』タグを付けて」で対象を抽出し、まとめてタグを付与/解除（同じ操作は冪等） |
| **CSV取込** | ドラッグ&ドロップ。列名の表記ゆれを自動吸収し、重複を検出してプレビュー後に取込 |
| 並び替え | 最近の更新・氏名（あいうえお順）・会社名・名刺交換日 |
| お気に入り | カード右上の★で即時トグル。サイドバーに件数表示 |
| 詳細表示 | 右サイドドロワー。メール/電話/Webサイトへのリンク、各項目のワンクリックコピー |
| 登録・編集 | モーダルフォーム。氏名必須・メール形式チェック・タグはカンマ区切りで最大12個 |
| 削除 | 詳細ドロワーから確認付きで削除 |
| CSV出力 | BOM付きUTF-8（Excelでそのまま開ける）。全件を氏名順で出力 |
| キーボード操作 | `/` で検索フォーカス、`n` で新規作成、`Esc` で閉じる |

## AIアシスタント

右下の「AI」ボタンから開きます。話しかけると検索条件に変換され、一覧が絞り込まれます。

| 発話例 | 動作 |
| --- | --- |
| 広報部署だけまとめて | 部署で絞り込み（語彙から最も近い部署を選択） |
| 営業の人をあいうえお順で | タグ絞り込み＋氏名順ソート |
| お気に入りだけ | お気に入りのみ表示 |
| 名刺は何枚ある？ | 総数・お気に入り数・部署別の集計を表示 |
| CSVで出して | CSVをダウンロード |
| 鈴木さんの部署を営業部に変えて | **編集案**を差分付きで提示（適用は要確認） |
| 山本さんのメモを「β版の反応が良い」に変えて | メモの差分を提示 |
| 広報の人に「展示会」タグを付けて | 対象一覧＋件数を提示し、まとめて付与 |

### AIによる編集（提案 → 確認 → 適用）

「AIに書き換えさせる」と聞くと便利ですが、**勝手にDBが変わるのは危険**なので、2段階に分けています。

1. AIは `changes`（変更したい項目だけ）を返すだけ。**この時点ではDBに一切書き込まれません。**
2. サーバが現在値と突き合わせて **項目ごとの差分（変更前 → 変更後）** を作り、画面に提案カードとして表示します。
3. ユーザーが **「適用する」** を押したときだけ `POST /api/assistant/apply` が書き込みます。「キャンセル」なら何も変わりません。

**安全側に倒している点**

- **許可リスト方式**: 書き換え可能な項目は `EDITABLE_FIELDS`（氏名・ふりがな・会社・部署・役職・メール・電話・携帯・Web・住所・メモ・名刺交換日・お気に入り・タグ）に限定。`id` / `created_at` / `updated_at` などは送られてきても無視します。
- **適用時も再検証**: 適用リクエストの `changes` は再度 `normalizeChanges()` を通します。AIの出力も画面の表示も信用しません。
- **対象を推測しない**: 氏名・会社名から候補を絞り、**同点の候補が複数あるときは適用せず候補を返します**（`edit.status = 'ambiguous'`）。0件なら `not-found`。
- **削除は不可**: 削除を頼まれても `intent='help'` で断ります。
- **件数を捏造させない**: 一括タグ操作の対象件数は、AIが言った数ではなくサーバが `filters` で引き直した実数です。
- **冪等**: すでに付いているタグの再付与などは `updated: 0` となり、二重に書き込みません。
- **AI停止時は推測しない**: 編集系の指示をAIなしで解釈するのは危険なので、フォールバックでは「解釈できませんでした」と返します。
- **表現**: 提案時のメッセージは「〜に変更します」（完了形にしない）。適用済みと誤読させないためです。

**設計上の要点**

- AI の役割は **「自然言語 → 検索条件(JSON)」の変換だけ** に限定しています。件数の集計・絞り込みの実行は必ずサーバ側の SQL が行うため、モデルが数字を捏造しても結果には影響しません。
- プロンプトには **実DBに存在する部署・会社・タグの語彙だけ** を渡し、存在しない値を捏造させないようにしています（受け取った値も語彙と照合して補正）。
- AI が使えない場合（キー未設定・障害・レート制限）は **ルールベースのフォールバック** が働き、機能が止まりません。この場合レスポンスの `source` が `fallback` になります。
- APIキーはサーバ側の環境変数のみで扱い、ブラウザには一切露出しません。

## CSV取込

トップバーの「CSV取込」から、ファイルをドロップまたはクリックして選択します。

- **文字コード自動判定**: 日本語版Excelの既定である Shift_JIS も、UTF-8 として読んで文字化けを検出した場合に自動で読み直します。
- **表記ゆれの吸収**: 「氏名 / お名前 / Name」「会社名 / 勤務先 / Company」「部署 / 所属 / Department」などを正規化して対応付けます。完全一致しない場合は部分一致で救済します。
- **プレビュー**: 読み取り件数・新規・重複・スキップを表示し、どの列をどの項目として解釈したかをチップで可視化します。
- **重複検出**: 氏名＋会社名を正規化（空白・「株式会社」等の法人格を除去）して判定します。初期設定では重複をスキップします。
- **制限**: 2MB / 2,000件まで。RFC4180準拠（引用符内のカンマ・改行・`""` エスケープに対応）。

## 画面・APIエンドポイント

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/` | アプリ本体（HTMLシェル） |
| GET | `/api/cards` | 名刺一覧。`q` `tag` `company` `department` `favorite=1` `sort` で絞り込み/並び替え |
| GET | `/api/cards/:id` | 名刺1件取得 |
| POST | `/api/cards` | 名刺作成 |
| PUT | `/api/cards/:id` | 名刺更新 |
| PATCH | `/api/cards/:id/favorite` | お気に入りトグル |
| DELETE | `/api/cards/:id` | 名刺削除 |
| GET | `/api/meta` | 総数・お気に入り数・会社/部署/タグ一覧 |
| GET | `/api/export.csv` | CSVダウンロード |
| POST | `/api/import/preview` | CSVを取り込まずに解析（本文は `text/csv`） |
| POST | `/api/import/commit` | 解析済み行を登録。`{rows, skipDuplicates}` |
| POST | `/api/assistant` | 自然言語を解釈。`{text}` → intent/filters/該当カード、`update`/`bulk_tag` では `edit`（差分・候補）も返す |
| POST | `/api/assistant/apply` | 編集の適用。`{mode:'update', cardId, changes}` / `{mode:'bulk_tag', tagOp, cardIds}`。`dryRun:true` で差分のみ |

`sort` の値: `updated`（既定） / `name` / `company` / `met`

## 環境変数

AIアシスタントは以下の環境変数を使います（未設定でもフォールバックで動作）。

| 変数 | 用途 |
| --- | --- |
| `OPENAI_API_KEY` | LLM APIキー（**サーバ側のみ。ブラウザに露出させない**） |
| `OPENAI_BASE_URL` | OpenAI互換エンドポイント |
| `AI_MODEL` | 使用モデル（既定 `gpt-5-nano`） |

ローカル開発では `.dev.vars`（gitignore済み）、本番では `wrangler secret put` で設定します。

## データ設計

D1（SQLite）の `cards` テーブル1枚で構成。

| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | INTEGER PK | 連番 |
| `name` / `name_kana` | TEXT | 氏名 / ふりがな |
| `company` / `department` / `position` | TEXT | 会社名 / 部署 / 役職 |
| `email` / `phone` / `mobile` / `website` | TEXT | 連絡先 |
| `address` | TEXT | 住所 |
| `tags` | TEXT | タグのJSON配列（例 `["営業","決裁者"]`） |
| `memo` | TEXT | フリーメモ |
| `favorite` | INTEGER | 0/1 |
| `met_at` | TEXT | 名刺交換日（YYYY-MM-DD） |
| `created_at` / `updated_at` | TEXT | 作成・更新日時 |

- **ストレージ**: Cloudflare D1（バインディング名 `DB`）
- **初期化**: 初回アクセス時に `ensureDatabase()` がテーブルとインデックスを作成し、空ならサンプル12件を投入（isolate単位で1回だけ実行）
- **注意**: D1 の `exec()` はSQLを行単位で分割実行するため、複数行DDLは使えない。文ごとに `batch()` で実行している

## 使い方

1. 一覧から名刺カードをクリックすると詳細が右から開く
2. 「名刺を追加」または `n` キーで登録フォームを開く
3. 検索窓に会社名やタグ、メモのキーワードを入れると即座に絞り込まれる
4. サイドバーのタグ/会社をクリックで絞り込み、もう一度クリックで解除
5. `CSV出力` でバックアップやExcel取り込み用のファイルを取得

## 開発・デプロイ

```bash
npm install
npm run build                 # dist/ を生成
npm run preview               # http://localhost:3000 でローカル起動（D1 local）
pm2 start ecosystem.config.cjs # サンドボックスでの常駐起動

# テスト
node --experimental-strip-types scripts/csv-test.mjs  # CSVパーサ単体（32項目）
node scripts/ui-test.mjs                              # 画面の回帰（31項目）
node scripts/ai-csv-ui-test.mjs                       # AI/CSV UI（30項目）
python3 scripts/ai-intent-test.py                     # AI意図解釈の精度確認
```

本番でD1を使う場合は、`wrangler d1 create webapp-production` でデータベースを作成し、
発行された `database_id` を `wrangler.jsonc` に設定してください。
AI用のシークレットは `npx wrangler pages secret put OPENAI_API_KEY` で登録します。

```bash
npx wrangler d1 create webapp-production
npx wrangler pages secret put OPENAI_API_KEY
npx wrangler pages secret put OPENAI_BASE_URL
npm run deploy
```
